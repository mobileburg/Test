# Контур обучения распознавания

Это воспроизводимая основа модели, а не неконтролируемое «самообучение» в production.
Исправления пользователей сначала попадают в очередь, проходят модерацию и только
после этого могут войти в следующую версию индекса.

## Архитектура

1. `ingest_cbr.py` получает русскую разметку из официального SOAP API Банка России.
2. `ingest_cbr_images.py` загружает официальные изображения аверса и реверса
   из каталога Банка России и помечает их как доверенные эталоны.
3. `ingest_wikimedia.py` получает изображения российских монет из Wikimedia Commons
   и пропускает файлы без свободной лицензии.
4. `build_dataset.py` объединяет доверенные эталоны, свободные изображения и
   одобренные пользовательские исправления.
5. `train.py` строит версионированный индекс визуальных признаков CLIP.
6. `predict.py` возвращает ближайшие совпадения и ссылки на первоисточник.
7. `service.py` предоставляет тот же индекс приложению через HTTP API.
8. Исправления из приложения сохраняются в серверной очереди. Обычный пользователь
   получает статус `pending` — в `build_dataset` / `train` запись не попадает,
   пока администратор не одобрит её. Оценка администратора сразу получает
   `approved` и может войти в следующую сборку индекса.

Модель использует few-shot подход: новая одобренная фотография добавляет новый
эталон при следующей сборке индекса. Это безопаснее автоматической подстройки весов
на непроверенных данных и подходит для классов с малым числом изображений.

## Источники

Реестр находится в `sources.json`. Автоматически включены только:

- **Банк России** — бесплатный общедоступный API; требуется ссылка на источник;
- **Wikimedia Commons** — изображения проверяются по лицензии каждого файла.

Найдены также RARITETUS, Конрос, SovMint, coins.su и Мешок. Их сбор отключён:
публичный просмотр не означает разрешение на массовое копирование и обучение.
Источник включается только после получения письменного разрешения или ясной
лицензии на соответствующие данные и изображения.

## Сбор небольшого набора

```bash
python3 ml/ingest_cbr.py --from-year 2020 --to-year 2026
python3 ml/ingest_cbr_images.py --limit 100
python3 ml/ingest_wikimedia.py --limit 100 --depth 3
python3 ml/build_dataset.py
```

## Построение индекса

Для ML-зависимостей рекомендуется отдельное окружение:

```bash
python3 -m venv .venv-ml
. .venv-ml/bin/activate
pip install -r ml/requirements.txt
python3 ml/train.py
```

Проверка фотографии:

```bash
python3 ml/predict.py photo.jpg --artifact ml/artifacts/<версия>
```

Каждый кандидат получает `model_card.json`, хеш датасета и статус
`candidate`. Публикация без ручной проверки качества не предусмотрена.

## API распознавания

После ручной проверки кандидата запустите сервис с конкретной версией индекса:

```bash
export NUMISMAT_MODEL_ARTIFACT=ml/artifacts/<версия>
export NUMISMAT_CORS_ORIGINS=http://localhost:5173
uvicorn ml.service:app --host 0.0.0.0 --port 8000
```

Приложение направляется на этот сервис переменной окружения:

```bash
VITE_RECOGNITION_API_URL=http://localhost:8000 npm run dev
```

Если переменная не задана, приложение использует `/api/v1/recognize` на том же
origin. Это удобно для production reverse proxy. Для Android APK необходимо
указать публичный HTTPS-адрес API во время сборки.

Проверка состояния доступна в `GET /api/v1/health`. Распознавание принимает
`multipart/form-data` с полем `file` в `POST /api/v1/recognize`; поддерживаются
JPG, PNG и WEBP размером до 15 МБ. Опционально: `exclude_catalogs` и `exclude_ids`
(каталожные номера или id отклонённых оценок), чтобы повторить распознавание
без уже отвергнутого класса.

Фидбек после скана: `POST /api/v1/feedback` (`coin_id?`, `photo`,
`predicted_catalog`, `verdict`: `correct|incorrect`, `comment?`, `retry?`).
Очередь модерации: `GET /api/v1/admin/feedback`,
`POST /api/v1/admin/feedback/:id/approve|reject`. Не-админ получает 403.
Оценка с клиента под `role=admin` сразу `approved`.

Личные кабинеты: `POST /api/v1/auth/register`, `POST /api/v1/auth/login`,
`GET /api/v1/me`, `GET/POST /api/v1/coins`. Фото сторон:
`POST /api/v1/coins/{id}/photo?side=obverse|reverse` (по умолчанию аверс),
`GET` с тем же `side`. Старое одно фото в `photo_relpath` считается аверсом.
Админка (только `role=admin`):
`GET /api/v1/admin/users`, `GET /api/v1/admin/users/{id}/coins`. Не-админ получает 403.
Как назначить admin: первый пользователь в пустой БД, либо `NUMISMAT_ADMIN_EMAIL`,
либо `python scripts/promote_admin.py email@domain`.

## Следующий этап backend

- хранить оригиналы в объектном хранилище, а не в БД;
- удалять EXIF и проверять MIME/размер;
- фиксировать согласие, автора и лицензию каждого изображения;
- разделять train/validation по физическому экземпляру монеты;
- измерять top-1/top-5 accuracy отдельно по эпохам;
- не показывать уверенный ответ ниже согласованного порога;
- поддерживать откат на предыдущую версию индекса.
